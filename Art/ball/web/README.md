所有座標以原始畫布左上角為原點，單位為原圖像素。保留 `1.PNG` 等原始編號和大寫副檔名。圖片沒有縮放、重新取樣或羽化。

## 定位與遮罩

`characters.json` 記錄來源路徑、各姿勢檔名、原始尺寸、完整 face 在 body 的位置、裁切矩形、新放置座標與安全邊界。

Lar 的共用遮罩已寫入每張輸出 PNG 的 Alpha，不需在網頁重複套用。共189個原本半透明的像素設為全透明，其座標和原始 Alpha 均記錄於 `face.mask.pixels`，座標相對於裁片左上角。RGB通道全部保留，其餘 Alpha 完全不變。這些189個像素在全部表情與各姿勢中均為相同的靜態輪廓，最終細節由原始 body 顯示。

Tivbo 裁片所有像素完全不透明，RGBA 均保持裁切前原值。

每側8個原圖像素的安全邊界與 body 一致。保留裁片內的整片繪畫內容，包括膚色，不使用只顯示差異像素的稀疏表情貼片。

## 產生與重新驗證

在專案根目錄執行：

```sh
node scripts/prepare-ball-faces.mjs
node scripts/prepare-ball-faces.mjs --verify-only
```

產生流程僅使用 Node 內建功能。來源限於現有的非交錯 RGBA8 PNG，會驗證 PNG CRC 及顏色描述資料。不進行色彩轉換，輸出保留來源 sRGB／ICC／gamma 等顏色區塊，採逐列自適應無損濾波與 DEFLATE level 9。原 EXIF、文字等非色彩中繼資料不複製到衍生檔。

兩位角色的所有檢查通過後才寫入圖片。若現有輸出 PNG 與即將生成的內容不同，停止而非覆寫。`--verify-only` 不寫入檔案，會從磁碟重新解碼並核對全部輸出、定位資料、原圖雜湊與驗證報告。

## 驗證範圍與目標

`verification.json` 包含141個原始檔案（125個face及16個body）的SHA-256、125個輸出PNG的SHA-256、實際容量及全部1000個組合的檢查結果。

目標由原始完整face與各姿勢建立：原face不透明部分的RGBA作為替換目標，原face透明處保留該姿勢的body。此目標不採用舊版「完整face以source-over直接疊在body上」產生的重複半透明邊緣。

檢查包括：

- 全部表情的Alpha形狀與基準一致。
- 所有繪畫差異都在核准裁切矩形內，而且差異像素完全不透明，保留最低色差的抗鋸齒細節。
- 安全邊界沒有繪畫差異，遮罩不移除任何表情變化。
- 全部8個姿勢在新裁片覆蓋區內的RGBA完全一致，裁片外的原face可見區也與相應姿勢相容。
- PNG編碼／解碼後的RGB與Alpha逐通道比對，僅允許Lar核准的189個Alpha變更。
- 63×8及62×8個組合，以整數預乘RGBA分子驗證標準source-over合成，容許差異為0，不採相似度或色差容忍門檻。
- 已另使用Apple ImageIO獨立解碼125張磁碟輸出，逐通道確認與原始裁片及核准遮罩一致。

這是原始解析度的像素與合成驗證。頁面共用 body 座標系合成後再整體縮放。像素驗證與 SVG 結構測試不取代各瀏覽器及裝置像素比例的視覺檢查。
